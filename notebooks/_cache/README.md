# `_cache/` 안내

`notebooks/`의 5개 노트북이 라이브 DB 쿼리를 매번 다시 하지 않도록 중간 결과를 저장해 두는 폴더다.

> **이 폴더의 파일은 저장소에 포함되지 않는다.** 제공받은 원본 데이터에서 파생된 파일이므로 `.gitignore`로 전부 제외되어 있고, 각자 로컬에서 노트북을 실행할 때 새로 생성된다. 캐시 파일 자체는 물론이고 그 스키마(컬럼 구성·행 수)도 외부에 공유하지 않는다.

## 동작 방식

- 각 노트북의 캐시 사용 셀은 `REFRESH` / `REFRESH_CACHE` 플래그를 가진다.
  - `False`(기본): 캐시 파일이 있으면 DB에 접속하지 않고 그대로 읽는다.
  - `True`: 쿼리를 다시 실행하고 캐시를 덮어쓴다.
- 05번은 `cache_or_query()` 패턴과 `CACHE_DIR = "./_cache"`를 쓴다. 캐시 유무와 무관하게 항상 DB에 접속하는 셀(전처리 테이블 존재 확인 등)이 일부 있다 — 최상위 `README.md`의 실행 방법 참고.
- 03번의 리텐션 원본 쿼리는 캐시를 쓰지 않아 실행할 때마다 DB에서 새로 조회한다.

## 캐시가 없을 때

로컬 MySQL 접속만 되어 있으면 각 노트북을 위에서부터 순서대로 실행하는 것만으로 필요한 캐시가 다시 만들어진다. 접속 정보는 환경변수 `RECRUIT_DB_URL`로 주입한다(최상위 `README.md` 참고).

## 알아둘 점

- 폴더에 파일이 남아 있다고 해서 현재 노트북 코드가 그 이름을 반드시 쓴다는 보장은 없다. 이전 작업 과정에서 남은 캐시가 섞여 있을 수 있으며, 지워도 5개 노트북 실행에는 영향이 없다.
- 노트북 코드와 캐시 파일의 스키마가 어긋나면(이전 버전 컬럼명으로 저장된 경우 등) 05번은 필수 컬럼 검증에 걸려 자동으로 다시 계산한다. 다른 노트북에서 비슷한 오류가 나면 해당 캐시 파일을 지우고 `REFRESH = True`로 한 번 실행하면 된다.
